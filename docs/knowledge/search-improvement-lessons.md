# 探索改善の教訓

CPU探索エンジンの改善で得られた知見をまとめる。言語非依存の教訓として、今後のZig版改善に活用する。

## v1 改善の教訓（2026-03）

### 1. 探索深度 > 評価精度

depth 1の差 = Elo 20-50。末端評価の改善（+500スコア）より、同じ時間でより深く読めることの方が棋力に直結する。

### 2. 「理論的に正しい」!= 「実装で有効」

NMP活三チェックは理論通りだが、連珠では活三が常時存在するためNMPがほぼ全面無効化された。結果: depth 6到達率 -15.8pt、Elo -81.6。

### 3. 実装前に頻度を測定する

改善対象のパターンが実際にどの程度発生するか、事前に計測すること。頻度が低いパターンの改善は効果が薄い。

### 4. 末端評価ギャップは「原因」ではなく「相関」

ブランダー3000-5000スコア差と末端評価ギャップに相関はあるが、末端評価を改善してもブランダーは減らなかった。

## プロファイリングで判明したコスト分布パターン

10局 hard vs hard での計測結果（探索 depth 6 時点）:

| コンポーネント     | 割合     | 備考                              |
| ------------------ | -------- | --------------------------------- |
| 候補手生成+ソート  | **53%**  | 内訳: 脅威検出 35% + 局面評価 15% |
| 盤面評価           | **41%**  | QSearchのstand-patで大量呼び出し  |
| ミセ手ボーナス計算 | **9.4%** | 局面評価内で最重                  |
| VCFチェック        | 4.3%     | 呼び出し少ないため影響小          |

### 枝刈り統計

| 指標              | 値        | 示唆                        |
| ----------------- | --------- | --------------------------- |
| NMPカットオフ率   | 61.2%     | NMP自体は有効に動作         |
| LMR発動率         | 2.7%      | 全ノード中わずか            |
| LMR re-search率   | **4.7%**  | 低い → 削減量を増やす余地大 |
| LMR moveIndex 5+  | **96.3%** | 後方候補手で積極削減可能    |
| QSearchノード比率 | **48.2%** | 全ノードの半分              |
| QSearch平均分岐   | 1.85手    | 小さい                      |

## 棄却した施策と理由

| 施策               | 棄却理由                                                       |
| ------------------ | -------------------------------------------------------------- |
| 脅威チェック高速化 | 計測で1-10us/回と判明。コスト無視可能                          |
| QSearch活三追加    | QSearch分岐1.85手 → 活三追加で分岐爆発リスク（活三は常時存在） |
| 盤面評価の差分化   | 効果大だが実装コスト極高。他の施策を先に                       |

## ベンチマーク方針

- SPRTで早期停止を活用
- 改善ごとに個別ベンチ（複数施策同時は原因切り分け困難）
- 各施策実装後にre-search率等のカウンターを確認
