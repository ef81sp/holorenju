# horizon-flips-v2 の分類（静的評価の見落とし調査）

対象: `bench-results/horizon-flips-v2.jsonl` 142 局面（全件 7 石・白番の根、hard depth7/100k で 4 手進めた各手の score が手番視点で |score|>2000 に反転したもの）。
設計メモ `docs/plans/eval-r4-2026-09-11.md` §6 の入力。

## 0. 手法（スクリプト: 同ディレクトリ `horizon-flips-classify.ts` → `-deep.ts` → `-pv.ts` → `-vct8.ts` → `-features2.ts`。最終 JSON は `horizon-flips-final.json`）

- `plies[i].score` は「i 手目を指す直前の局面を探索した結果」で **手番視点**（gen-opening-suite-worker.ts）。反転 ply = |score|>2000 になった最初の手、勝者 = その符号が正なら手番側、負なら相手。
- 準備局面 = 勝者が手番の局面（勝者が反転手を指す側ならその直前、相手なら反転手直後）。
- (a) 静的評価 = `WasmBoardEvaluator.evaluateBoard(hard.evaluationOptions)`（prospect 基底）。
- (b)(c) VCF = `findVCFSequence(depth 8, 無制限)`、VCT = `findVCTSequence(depth 4, 200k)`。C 候補は追加で VCT depth 6/400k と depth 8/1M を試した。
- (d) `extractProspectFeatures` の符号規約から勝者側／敗者側の空点カテゴリ計数を復元し、根→準備局面の差分を取った。
- 分類（最終）: **A** = 根の時点で勝者に VCF/VCT がある、**B** = 準備局面で初めて VCF(8)/VCT(4, 200k) が成立、**B-deep** = VCT 6/400k か 8/1M でのみ成立（探索予算寄り）、**C** = 上記すべてで詰みが出ない、**D** = 禁手絡み（VCF/VCT の isForbiddenTrap または反転手が禁手）。

実行時間: 分類 80 s、準備局面の深掘り 45 s、C/B-deep の PV 取得 214 s、VCT 8/1M 再確認 80 s、候補特徴計測 2 s。合計約 7 分（M 系 Mac、1 プロセス）。

補足:

- A は全件「白番の根で黒に VCT（len 7〜13）または VCF が既にある」。白の depth7 探索が黒の追い詰めを見えていない＝探索予算（被追い詰め判定）の問題。長さの内訳 VCF 8 / VCT7 5 / VCT9 6 / VCT13 3。
- B の追い詰め長: 3 手 4、5 手 10、7 手 27、9 手 9、11 手 1。初手の種類は 三 44 / 四 5 / 四三 2。攻め手に含まれる三の数は 1 個 13 / 2 個 35 / 3 個 3。
- C 47 件の準備局面を hard で再探索した PV の攻め手列: 42/47 が「三」で始まり、「三 (受け) 三 (受け) 三 (受け) 四」が最頻（8 件）。PV 末端の静的評価は ≥5000 が 21 件、2000〜5000 が 10 件、<2000 が 16 件。PV に ミセ手／両ミセ手 を含むものが 7 件。PV 末端で勝者に四三点がある 7 件、VCF がある 34 件。
- C のうち勝者が反転手を指す側（mover）は 46/47。再探索（時間モード、非決定的）で |score|>2000 が再現したのは 43/49（B-deep 分を含む mover 集合）。
- 根の静的評価（白視点）は探索 score より中央値で 854 低い（49 件で −1000 未満）。静的評価は手番側に対して悲観的な系統オフセットがある（WAIT/TURN の非対称）。
- 敗者側が根で VCF/VCT を持っていた局面が 38 件（白番の根で黒の四追いが残っており白が受ける形）。これは反転の原因ではなく前提条件。

## 3. 代表例 5 件（座標は H8 形式、左下原点）

1. **A（根に黒の VCT13）idx 9**: 黒 H9 H8 F7 F6 / 白 I8 G7 F5、白番。plies G6:493 H7:731 H10:−676 H6:99999。根で黒に VCT `G8 E6 H7 H6 F9 I6 H11 H10 F8 F10 E8 D8 G10`（13 手）があるが白 depth7 は +493。準備局面（白 G6 黒 H7 白 H10 後）でも黒 VCT9。→ 被追い詰めの探索予算。
2. **B（三→四三の 5 手追い詰め）idx 3**: 黒 H8 J8 K8 J7 / 白 G8 I7 I6、白番。plies J6:196 L8:407 I8:0 I5:−3031。白 J6 黒 L8 白 I8 の後、黒手番で黒は −3031。白の追い詰め `H7 J5 G6 F6 J9`（三・四・四三）。準備局面の白の静的評価は +341、勝者側カテゴリは SOLO_F3 6・F3_F2 1・SOLO_B4 1 で敗者側と同程度。
3. **B（根から 1 手で被追い詰め）idx 140**: 黒 G8 H8 J8 G5 / 白 H7 I7 I6、白番。plies I8:500 I9:−99999。白 I8 の直後、黒は受けなしで −99999。白の追い詰め `J7 K7 F7`（3 手）。根の静的評価は白視点 −2501（探索は +500）。根の時点で白に「一手で 3 手追い詰めが成立する三点」があるが、現行カテゴリでは SOLO_F3 の 1 個としてしか見えない。
4. **C（三 三 三 四の連打）idx 133**: 黒 H8 K7 J6 I5 / 白 G7 H7 G6、白番。plies H4:−247 K5:−378 I7:3302 F7:−1383。準備局面（白 H4 黒 K5 後、白番）で VCF/VCT なし（VCT 8/1M でも無し）。hard PV `I7 E7 E4 I8 G8 G5 D3` = 三(受け)三(受け)三(受け)四、末端の静的評価 +6837。準備局面の静的評価は白視点 −2804、根も −4846（探索 −247）。静的評価が手番側を大きく悲観し、探索が連続三の先で四三／活四点（TURN 3000/4500）を見つけて反転する。
5. **C（ミセ手を含む追い詰め）idx 10**: 黒 J9 H8 F7 F6 / 白 I8 G7 F5、白番。plies I5:399 H6:92 G5:9095 H5:−99999。準備局面（白 I5 黒 H6 後）で hard は G5=+9095。PV `G5 H5 H7 F8 G6 E4 G8` = 三(三)ミセ(静手)四三(受け)四。VCT 探索は四・三のみを攻め手にするためミセ手を挟む追い詰めを見つけない。静的評価にも「次に四三点ができる空点（ミセ点）」の概念がない。

副次的な観察（要確認）: idx 6（黒 H9 I9 H8 J7 / 白 G8 H7 I7、白 F9 黒 I6 白 I8 の後、黒番）で hard は J9=99999。J9 は三かつミセ（L9）で、白の受け K9/G9/L9 のいずれにも黒の VCT/VCF（`J8 J6 J10 J11 K11` または `L9 K9 K8`）を個別に確認したが、`findVCTSequence`（depth 8, 1M）は J9 からの追い詰めを返さない。VCT 探索の受け手列挙か深さの数え方に穴がある可能性。

## 4. 現行 17 カテゴリで表現できていない形の候補（根拠つき）

1. **手番付きの「三の連鎖」＝脅威状態×手番テーブル（§6 候補の裏付け）**。準備局面で勝者と敗者の計数は同等（AUC 0.36〜0.56）だが結果は手番側の連続三で決まる。C の PV 最頻は「三・三・三・四」、B の攻め手は三が 2 個含むものが 35/51。現行の TURN/WAIT 差（SOLO_F3 141 vs 106、F3_F2 254 vs 184）では「手番側が三点を 2 本以上の別ラインに持つ」初動の価値を表せない。提案: (自分の三点ライン本数バケット, 自分の四点有無, 相手の三点ライン本数, 相手の四点有無, 手番) を索引とするテーブルを prospect の上に載せ Texel で適合（加算パッチでなく基底の一部として）。
2. **ミセ点（置くと自分の四三点が生まれる空点）**。C の PV 7/47 にミセ手または両ミセ手が入り（idx 10、idx 6 は三兼ミセ）、VCT 探索も静的評価もこれを見ない。現行では FOUR_THREE（既に四三点）しかなく、その 1 手前が SOLO_F3/F3_F2/SOLO_B4 に埋もれる。提案: 空点分類の第 3 段として「その点に置いた後に FOUR_THREE 以上の空点が同色に ≥1 個できる」を判定するカテゴリ（三兼ミセと静手ミセを別に）。計算は三点／四点候補のみ対象なら O(脅威手数 × 4 方向窓)。
3. **三を打った後に受けの全てで三点が純増する三（自己強化する三、連続三の種）**。C の PV 「三 (受け) 三 (受け) 三」を静的に近似する 1 手先特徴。勝者根 vs 対照根で AUC 0.58/0.67 と現行の三点数（0.65/0.71）と同程度の分離だが準備局面では敗者側の方が多く（AUC 0.36）、手番と組み合わせないと逆効果になる。提案 1 の索引に「連鎖可能な三点本数」を使う形で統合するのが妥当。単独カテゴリ化は推奨しない。
4. **上位 2 方向への畳み込みで落ちる同時形（b4+b3 → SOLO_B4、f2+b3 → SOLO_B3、f2×3 → DOUBLE_F2）**。B/C の準備局面で勝者側 SOLO_B4 ≥1 が 31/51、23/47（根では 3/51、6/54）と急増しており、四点が三点と共存する局面で反転している。ただし今回の計測では per-cell の方向コードを復元していないため「畳み込みで消えた情報が効いている」ことは未検証。優先度は 1・2 より下。
5. **被追い詰め側の探索レバー（評価ではなく探索）**: A 22 件は根で黒に VCT7〜13 があり、白の探索は見えていない。相手側の追い詰め判定（strict VCT）を根／1 手目で 25 ms 級のプローブとして走らせる余地。評価基底の課題ではないので §6 の範囲外として記録のみ。

## 5. 制約・注意

- VCT の depth 引数の数え方（攻め手数か手数か）は未確認。B-deep の分類境界はその解釈に依存する。
- 対照群は `opening-suite-plycheck-v2.jsonl` の非反転（全 ply |score|≤700、終局なし）先頭 400 局面。
