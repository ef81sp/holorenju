## 1. 設計

### 1.1 テーブル（36 重み・反対称）

- 状態 s(P, O) = (t3(P) バケット, f4(P), t3(O) バケット, f4(O))。三点数 t3 = カテゴリ SOLO_F3 / F3_F2 / F3_B3 / DOUBLE_THREE_WHITE / FOUR_THREE の**点数**（上位 2 方向畳み込み後のカテゴリ計数。第 3 方向以降の f3 は数えない）、四点有無 f4 = SOLO_B4 / B4_F2 / FOUR_THREE / SOLO_F4 / DOUBLE_FOUR_WHITE の点数 > 0。
- **重みは 1 テーブル `T[s]`**。評価は P 手番なら `+T[s(P,O)]`、O 手番なら `−T[s(O,P)]`、`.average` は `divTrunc(T[s(P,O)] − T[s(O,P)], 2)`。TURN/WAIT の 2 表にすると `combineFromSums` の反対称性から WAIT 表が TURN 表の鏡像に決まり、特徴列が完全共線になる（v1 の 72 重みは誤り）。特徴は「手番側を P とした s(P,O) の one-hot」で 34 + |S| 次元。
- 索引の粒度は **Phase 0 で決める**（§2）。候補:
  - A（粗）: t3 {0, 1〜2, 3+} × f4 {0,1} × 相手同様 = 36 状態。**占有が飽和しており不採用の公算大**（上記地形）。
  - B（細）: t3 {0, 1〜2, 3〜4, 5〜6, 7+} × f4 {0,1} × 相手同様 = 100 状態。
  - C（本数）: 三点を持つ**別ラインの本数**（ProspectState の dir_code から方向別 f3 の有無で近似）。分析 §4.1 の原案に最も近いが、34 特徴からは復元できず Zig の per-cell 情報が要る（Phase 0 では扱えない）。
  - 採用条件: 上位 3 状態の占有が 50% 未満、かつ希少状態（< 100 行）を除いた状態数が 20 以上。
- 仮説（§2 で検証する、前提にしない）: 「同じ形なら手番側が得」の非線形化（tempo）だけがこの表で表せる。分析が言う「連鎖の幾何」（別ラインか、受けで新しい三が生えるか）は載らないので、効果があっても小さい可能性が高い。

### 1.2 Zig 実装（Phase 1、Phase 0 通過時のみ）

- 集計の SSoT: `ProspectSums { sum: [2][2]i32, cat_count: [2][CAT_COUNT]u8 }` を導入。`evaluateFull` は cells から一時 ProspectSums を作り、`ProspectState` は同型を差分維持（`subtractContribAt/addContribAt` で `CELL_CAT` 参照 2 回に cat_count ±1 を同居。`updateNeighborDirections` の early-skip は不変）。`combineFromSums(sums, persp, stm)` がテーブル項を**クランプ前**に合成。`extractFeatures` も同じ aggregate から 34 + |S| を生成（Σ features × weights == raw のテストを新次元に拡張。`incremental_eval.zig` の Debug 等価検証も無改修で覆う）。
- 索引の SSoT: `threatClass(cat) -> {three, four}` を `CellCat` の exhaustive switch で comptime 定義、`bucket3/bucket4/threatStateIndex` を純関数に、`THREAT_STATE_PARAM_NAMES` は同じ索引関数から comptime 生成（名前と索引のドリフト不能化）。`PROSPECT_PARAM_COUNT` を `CAT_COUNT*2 + THREAT_STATE_COUNT` に拡張し、`setProspectParam/getProspectParam` は offset ≥ 34 をテーブルへ。id は 134〜（`PROSPECT_TSTATE_<t3P><f4P><t3O><f4O>`）。`main.zig` の feature buffer は同定数から自動追従。
- TS 側: `scripts/lib/threatState.ts` に `THREE_MAKER_CATEGORIES` / `FOUR_MAKER_CATEGORIES`（`PROSPECT_CATEGORIES` の要素で型制約）、`bucket3/bucket4/threatStateIndex`、`synthesizeThreatStateFeatures(features34)`、`THREAT_STATE_PARAM_NAMES` を一本化。`evalParams.ts` の名前表と Phase 0 合成が共用。`PROSPECT_FEATURE_COUNT` は `+ THREAT_STATE_COUNT`。
- パリティ: `*.wasm.test.ts` でコーパス数百行＋乱数盤について「wasm `extractProspectFeatures` の状態部分 == `synthesizeThreatStateFeatures(34 部分)`」をビット一致で固定。Phase 1 以降、TS 合成は**パリティテストの oracle 専用**（本番の抽出は wasm 一本。CLAUDE.md の二重実装規約）。
- 既定値は Phase 2 の量子化結果を焼き込み（TS に既定値を複製しない）。legacy 基底・下位難易度（bit18/bit24 分岐）には影響なし。
- NPS: 変化セルあたり数命令の追加。P1 の受入条件に Gate 0 相当の NPS 比（固定局面プローブ）**±3% 以内**を置く。

### 1.3 Texel 適合と量子化（Phase 2）

- 特徴 34 + |S| で `prospect-texel.ts`（rapfi 教師、K=200、k=5）。Phase 0 の合成特徴（TS）から fit/anchor を実行できる（Zig 抽出との一致はパリティテストで保証）→ **P1 と P2 は並列**。
- anchor（`prospect-anchor.ts`）: アンカー 6 セル据え置き。テーブル列は密なので support = 状態の行数。**希少状態（< 100 行）は baseline 固定（初回は 0）**。スケール s は 34 セル＋テーブルの合成 dot で `legacy std` に合わせる。テーブル項はクランプ前の raw に加算する（線形モデルと一致）。fit の weightNames は `threatState.ts` の正準名で出力（Phase 2 で流用可能に）。
- 反復上限: `fitLogistic` の `maxIterations` を 20,000 に上げ、反復数と最終 relChange を出力して収束を確認。

## 2. Phase 0: オフライン事前反証（Zig を触らない、半日）

順に実行し、各段で撤退できる:

1. **残差診断（5 分）**: r4 の 34 セル fit の残差（texelFit の損失定義どおり）を索引 A / B の状態でグループ化し、行数・平均残差・SE を表にする。one-hot の最適係数 ≈ 状態別平均残差なので、「状態別平均残差で補正した予測の MSE」が改善の**上限近似**になる。**null 対照**: 状態ラベルを行間でシャッフルした索引で同じ計算（×3）を行い、自由度だけで偶然出る改善を差し引く。上限改善（null 差し引き後）が 2% 未満なら**ここで撤退**（テーブルは線形和に情報を足さない）。
2. 占有表: 索引 A / B の状態別行数。上位 3 状態 ≥ 50% の索引は不採用。
3. 同時再適合（残差診断が 2% 以上のとき）: 同一 fold（seed=42）で M0（34）/ M0b（34 + 定数列＝切片対照）/ M1（34 + one-hot |S|）/ M2（同じ占有分布の無関係索引、例: 石数バケット × 相手石数バケット）を fit（rapfi 教師のみ、min-support 100 を Phase 2 と同じく適用、反復上限 20,000）。判定は **同一 fold の対差 Δ の平均 ± SE と 5/5 fold で改善**、かつ M1 − M0b の改善が M2 − M0b を 5% 以上上回ること。2% 未満で撤退。
4. 診断: 状態重みの符号・単調性（t3(P) が増えると正か、相手の三点で負か）。「両者 3+」状態の重みが SOLO_F3 の TURN−WAIT 差（141 − 106）の再表現を超えているか。「手番側 3+ かつ相手四点なし」の重み。
5. horizon-flips 側の反証（TS 合成で可能）: 142 局面の根＋準備局面＋対照局面で M0/M1 の静的評価を出し、(i) 準備局面で M1 が勝者側へ動く件数、(ii) 対照局面で動かないこと、(iii) 「根は探索 score より中央値 854 悲観」が縮むか。
6. 索引 A/B とも撤退なら、索引 C（別ライン本数）は Zig の per-cell 情報が要るため「Phase 0 で止まれる」構造を失う。その場合は提案 2（ミセ点カテゴリ＝既存 per-cell 枠組みの拡張で構造変更が小さい）を次の候補にし、別メモにする。

補足: r3/r4 の「Rapfi 教師の損失改善は対局強さに直結しない」は同じ特徴集合の再適合に対する教訓。特徴を足す場合、損失改善（null 対照差し引き後）は「情報が増えた」ことの直接の証拠になるので Phase 0 のゲートに使う。**採否のゲートには使わない**（§3）。

## 5.5 結果（2026-09-11、Phase 0-1 残差診断）

- スクリプト scratchpad `p0-residual.ts`（実行 5 秒）、レポート `p0-residual-report.md`。M0（r4 最終重み、K=200）の train loss 0.076202 を再現。
- one-hot 上限（同時再適合なし。状態別に損失最小の補正 δ を 1 次元探索）:

| 索引         | 状態数       | M0 → M1             | 改善                          | null 対照（×3 平均） |
| ------------ | ------------ | ------------------- | ----------------------------- | -------------------- |
| A（粗、36）  | 36/36 占有   | 0.076202 → 0.074984 | **1.60%**                     | 0.07%                |
| B（細、100） | 100/100 占有 | 0.076202 → 0.074239 | **2.58%（logit 最適 2.83%）** | 0.16%                |

- セグメント別（B、全体係数）: kifu/06 2.0% / 08 3.6% / 09 1.5% / book 32%（M0 が小さく行数も少ないので過適合込み）。
- 残差の構造: 「両者に四点あり」（占有 26%）は残差 ≈ 0。**「相手に四点なし」で手番側の三点が多いほど線形和が過小評価**（T3≥3・O4=0: 11,420 行 +0.050 SE 0.002、T3≥5: +0.071、T3=7+: δ ≈ +180〜230 eval）。逆に手番側が空で相手に三点 3+ は過大評価（−0.117）。三点数に対する非線形（加速）と「相手四点の有無」との交互作用の 2 点に集約される。
- **判定: 撤退（Phase 0 で停止）**。索引 A は閾値 2% 未満、索引 B は 2.8% で保留帯だが、r4 の教訓（コーパス内損失 3% 改善で Elo ≈ 0）から、テーブル 36〜100 重みの Zig 実装（1 日＋ゲート 10 h）に見合う +10 Elo は見込めない。
- 将来候補（別メモ、着手は保留）: 同じ信号を 2〜4 パラメータで拾う非線形項（三点系カテゴリ計数の二乗項、「相手に四点なし」条件付き係数）。自由度が小さく、Zig 実装も `ProspectSums` の cat_count から O(1)。ただし期待値は上限 2.8% の範囲内。
- eval 側の総括: 単セル摂動（±10）→ 多様コーパス再学習（−8.6）→ 脅威状態テーブル（上限 2.8%）と 3 段で当たり、**prospect 基底の線形和に残る信号は小さい**。次に効く可能性があるのは per-cell の新カテゴリ（ミセ点）か、探索側（相手側追い詰めプローブ、horizon-flips A 22 件）。
