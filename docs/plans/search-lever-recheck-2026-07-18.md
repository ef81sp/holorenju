# 探索レバー再収穫の検証（2026-07-18）— 結論: 空振り（深さは prospect 基底でも効かない）

## 目的

「深さは Elo に効かない」という過去の結論（時間スケーリング 208 局、threatProbe NPS 調査）は**旧評価関数（legacy 基底）下**の測定だった。評価基底転換（空点プロスペクト + texel-r2、Gate 2 Elo +181）で葉評価が賢くなった今、深さの価値が変わっている可能性があるため再検証した。

## 方法

commit-bench の side 別レバーオーバーライド（PR #109 で追加: `--probe-off-a/b`, `--max-nodes-a/b`, `--max-depth-a/b`）を使用。

- **A 側（深読み構成）**: threatProbe OFF（NPS ~4〜5×）+ depth cap 7→12 + maxNodes 1M→3M
- **B 側**: main（ca66891）の hard そのまま
- 共通: 同一持ち時間（hard の timeLimit/dynamic time）、seed=20260718、randomFactor=0.02（シード付き実効ランダム化）、8 セット 416 局、SPRT 併用、jobs=5

### 前提調査で判明した拘束構造（スモークで実測）

| 構成                               | 平均深度 | 拘束                                                      |
| ---------------------------------- | -------- | --------------------------------------------------------- |
| hard 素 (probe ON)                 | 4.8      | dynamic time                                              |
| probe OFF のみ                     | 4.0      | **maxNodes 1M に早期到達**（NPS 5.5× のため）             |
| probe OFF + maxNodes 3M            | 4.0      | **depth cap 7**（早く着くだけ、10s 中 1.1s しか使わない） |
| probe OFF + maxNodes 3M + depth 12 | 6.0      | dynamic time（狙いどおり）                                |

過去計測「probe OFF で深度 5→12」は maxNodes/depth cap 制約外の計測であり、製品パラメータ下では cap 解放が必要だった。

## 結果（416 局完走）

| 指標         | A（深読み）                     | B（main）     |
| ------------ | ------------------------------- | ------------- |
| Elo          | **−12.5 [−46.1, +20.8]**        | 基準          |
| 勝率         | 48.2%                           | 51.8%         |
| 平均深度     | **5.62**（max 12）              | 4.16（max 7） |
| 総ノード     | 2.28G（4.4×）                   | 0.52G         |
| 平均思考時間 | 4884ms                          | 3924ms        |
| SPRT LLR     | −2.85（+30 Elo 仮説の棄却寸前） |               |

## 結論

1. **深さ→Elo≈0 は評価基底に依存しない**。葉が賢くなっても、hard の持ち時間帯では深度 +1.5（ノード 4.4×）が強さに転換しなかった。旧結論はタイミングノイズ下の測定だったが、シード付き実効ランダム化での再測定でも同じ結論
2. **threatProbe は ON 維持が正解**。probe は同等の強さを 1/4.4 のノードで達成しており、コスト対効果が高い
3. **探索系レバーの再収穫はクローズ**。CPU 強化の残りレバーは評価関数（次回 texel は序盤帯データ必須）・序盤ブック延長・コーパス多様化の側
