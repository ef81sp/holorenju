## ★ブック v2 プラン: Rapfi 誘導化（2026-07-17 ボス指示）

**動機（ボス）**: v1 のブック手は「エンジン自身の選択の凍結 + 安全検証」で、一般に知られた
定石と微妙に違う。対局 CPU としては許容でも、**振り返りツールが実際の最善手（定石）を
劣る手と表示するのは学習アプリとして不適**。

### 変更内容

1. **ラベル改名**（即時・独立）: 振り返りの「定石（ブック手）」→「**序盤ブック手**」
   （非定石手に「定石」の語を使わない。用語規約）
2. **ブック手の Rapfi 誘導化**: 既存エントリ（白 5,950 + 黒 1）の各 canonical 局面について
   Rapfi の選択手を取得し、**安全検証（決定化予算の VCF∪VCT チェック）を通過したものだけ**
   ブック手として採用。不通過・取得不能時は v1 の手（従来の検証済み手）に据え置き。
   - Rapfi 手の取得は corpus ラベリングと同じローカル運用（scripts/rapfi/、gitignore）。
     出力「canonicalKey → rapfiMove」JSONL を build-opening-book が `--rapfi-moves=` で消費
   - トラップ局面: Rapfi 手が検証通過ならそれを優先（randomPool の先頭固定 or 単独化）、
     不通過なら v1 生存手プール維持
3. **静的保証の置き換え**: v1 の「非トラップ=挙動不変」は放棄（全域で挙動が変わる）。
   新しい保証 = **全エントリが同一基準の安全検証済み** + ビルドレポートに
   「Rapfi 採用 / v1 据え置き / 検証不通過で却下」の内訳
4. **Elo ゲートの復活（今回は意味がある）**: v1 と異なり自己対局でも毎局ブック帯を通る
   挙動差になるため、**ベンチ経路にブック適用を配線**（cpu-bridge-worker にフラグ付きで
   ブック照会を追加。過去コミット比較を壊さないため既定 OFF・動的 import・try/catch）し、
   commit-bench（v2ブックコミット vs v1ブックコミット）で**中立以上**を確認
5. ゲート: 封鎖 61/61 維持・regression PASS・実資産ランタイムテスト・Elo 中立以上・
   振り返りで Rapfi 手（≈定石）に「序盤ブック手」ラベルが付くこと

### プランレビュー反映（2026-07-17、B1〜B3）

- **B1/B2（動機と作業の分離・注釈 top-N）**: ボスの動機の核心は振り返りの表示。これを
  最も直接に解くのは**注釈側の top-N 許容**。資産スキーマを「**着手用の手**（play）と
  **注釈用プール**（annotation: Rapfi 上位N + 検証済み既存手）」に分離する:
  - `isBookMove` は注釈プールとの一致で判定（同一局面の複数の有力定石を劣手表示しない）
  - 着手用の手 = Rapfi #1（安全検証通過時）/ 不通過は v1 手 — ボス指示の「着手も Rapfi 化」
  - **分離の効能**: Elo ゲートが失敗しても着手だけ v1 に戻せば済み、表示改善（注釈プール）は
    無傷で残る
  - Rapfi の MultiPV 相当（YXNBEST 等）が使えるか実装時に調査。不可なら
    プール = {Rapfi#1} ∪ {v1 手} ∪ {検証済み生存手} の合併で代替（N=2〜3 相当）
  - 残存限界の明記: ブック範囲外（ply>8・列挙外局面）の人間の定石手は従来どおり
    素の eval 判定。範囲は「序盤8手目までの列挙木」のまま
- **B3（ベンチ配線仕様）**: ①book 照会コード+資産は **worktreePath から動的 import**
  （host 側を使うと両側同一ブックになり比較が null 化）②モジュール/資産の不在（旧コミット）
  は book-OFF として扱いクラッシュしない ③ゲートは**同一バイナリで book-ON vs book-OFF の
  フラグ切替**（コミット差の交絡を排除、worktree 1本で済む）を優先構成とする
- **Elo ゲートの解釈（事前登録）**: 中立以上 → Rapfi 着手を採用。微負〜負 →
  着手は v1 に戻し注釈 top-N のみ採用（動機は注釈で達成済みのため、これは失敗ではない）
- Rapfi 手取得の再現性: off-book 局面は壁時計でなく**固定ノード/深さ予算**で照会（minor）
- 方向性の事前確認材料: 有名定石局面数点で「v1 手 / Rapfi 手 / 教科書定石」を並べた表を
  ボス報告に含める（「Rapfi≈定石」の仮定の見える化）

### コスト見積り

- Rapfi 手取得: ~6,000 局面 × 固定予算思考 ÷ 4並列 ≈ 25〜40分（ブックヒット時は即答）
- 変更エントリの安全検証: 変更率次第（30〜60% 想定）× 決定化チェック ≈ 1〜2h（6並列）
- Elo ベンチ（book-ON vs OFF、同一コミット）: r0.02×8セット ≈ 2.5h（夜間）

  注釈改善は独立に残る）

## 0. 目的と範囲（イシューレビュー S1/S2 反映で主張を精緻化）

- **目的**: hard（白番）の 4・6・8 手目を、安全性検証済みの手の参照に置き換え、
  **採掘で見つかった43局面のトラップ線（および同一 canonical 局面へ合流する経路）を封じる**。
- 副次効果（限定的）: トラップ43局面では検証済み生存手からのランダム選択が入る。
  **非トラップ局面は単一手のままなので「決定性搾取の全面解消」ではない**（将来、
  候補追加検証でランダム枠を広げる余地はある — コスト ≈ もう一回分の採掘×候補数）。
- **限界（明記）**: ブックの守備範囲は「列挙木（フィルタ通過の黒手）× VCF(16)∪VCT(6) 予算」。
  フィルタ外の黒手で列挙外局面に入れば従来どおり探索が受ける（同型敗着の残存はあり得る）。
- 範囲外（後続）: 黒番 hard ブック（採掘第2段が前提）、9手目以降、下位難易度。

## 3. 振り返りとの整合（イシュー B2 の解消）

- 問題: トラップ局面のブック手（生存手）は「素の探索が選ばない手」。振り返りが素の探索で
  注釈すると、**ブックが避けた敗着を「より良い手」として推奨し得る**（ユーザー向けの
  ミスリード）。
- 対応: 振り返りは着手選択にはブックを使わないままとするが、**注釈段階でブック資産を参照し、
  「打たれた手がブックに一致する場合は『定石（ブック手）』ラベルを付け、ミス判定と
  代替推奨を抑制する**（対象は ply≤8 のブック一致手のみ。資産の再利用であり、
  review.worker に openingBook の「注釈専用 API」だけを import する — 着手 API とは
  シンボルレベルで分離、worker バンドルには tree-shake で着手 API が入らない）。
- **例外（実装レビュー反映）**: 振り返りが当該手に強制負け（forcedLossType）を検出した
  場合は good 強制せず通常判定を出す（「定石なのに被詰み」の矛盾表示を防ぎ、将来ブックが
  古くなった場合も誠実な表示を維持）。
- 用語注記: 「定石（ブック手）」のラベル文言はボスレビューで要確認（「定石」は確立語、
  「ブック手」はエンジン用語の補助表記）。

## 5. 検証ゲート（事前登録・イシュー S4/S5 反映）

1. **トラップ封鎖**: severity-A 49 レコードの黒手順をブック有効 hard になぞらせ、全件で
   強制勝ち不成立。**ランダム候補はプール全手を決定的に列挙して検証**（1ドローではなく）
2. **regression-positions**: 全 PASS 維持
3. **挙動差の静的保証**（実装レビューで Elo ゲートから置換）: commit-bench の対局経路
   （cpu-bridge-worker → WASM 直呼び）はブック配線（cpu.worker）を通らず、かつブックの
   挙動差は敵対的列挙由来のトラップ局面に限られ自己対局では実質観測不能 = Elo ベンチは
   構成上 null テストになる。代わりにビルダーで **「非トラップ由来の全エントリ =
   ダンプの hard 実選択と完全一致」を assert** し、ビルドレポート（一致数・トラップ由来・
   彗星型除外数）を出力する。これにより「挙動差が検証済み生存手を持つトラップ局面に
   厳密に閉じる」ことが証明され、Elo 中立は構造的に保証される
4. **ブラウザ動作**: hard 対局でブック手使用のスモーク + 資産の遅延ロード確認 + 全テスト緑
5. **振り返り整合**: ブック手が「定石」ラベルになり敗着が推奨されないことをテスト棋譜で確認
