# 序盤定石ブックプラン（opening book v1: 白番 hard）v2

作成: 2026-07-16 ／ ステータス: /review 2観点（設計・イシュー）の blocker を反映した改訂版。
前提: トラップ採掘 run1 の判定「ブック化に進む」（severity-A 43局面。
`opening-trap-mining-2026-07-16.md`）。ボス承認済み（2026-07-16）。

## 0. 目的と範囲（イシューレビュー S1/S2 反映で主張を精緻化）

- **目的**: hard（白番）の 4・6・8 手目を、安全性検証済みの手の参照に置き換え、
  **採掘で見つかった43局面のトラップ線（および同一 canonical 局面へ合流する経路）を封じる**。
- 副次効果（限定的）: トラップ43局面では検証済み生存手からのランダム選択が入る。
  **非トラップ局面は単一手のままなので「決定性搾取の全面解消」ではない**（将来、
  候補追加検証でランダム枠を広げる余地はある — コスト ≈ もう一回分の採掘×候補数）。
- **限界（明記）**: ブックの守備範囲は「列挙木（フィルタ通過の黒手）× VCF(16)∪VCT(6) 予算」。
  フィルタ外の黒手で列挙外局面に入れば従来どおり探索が受ける（同型敗着の残存はあり得る）。
- 範囲外（後続）: 黒番 hard ブック（採掘第2段が前提）、9手目以降、下位難易度。

## 1. 一次データ: 「book ダンプ付き権威フル再実行」（両レビュー blocker の解消）

run1 の成果物はトラップ JSONL のみで、(a) 非トラップ局面の白8選択、(b) トラップ局面の
生存手（帰属分析の産物、未永続化）が残っていない。**再列挙の bit 一致に頼る構成は
ドリフトで未検証手を焼き込む穴になる**（イシュー B1・設計 B1/B2）ため、v2 では:

- `trap-mining.ts` に `--dump-book=<path>` を追加し、**1回の権威実行**で全てを出力する:
  - 全ノード（白4/白6/白8手番の canonical key）について: hard の選択手（**実機 10s**）と
    強制勝ちチェック結果
  - **トラップ検出時はその場で生存手導出まで実行**（白8 候補 PRECISE 上位 4〜5 ×
    VCF∪VCT チェック。run1 帰属分析と同じ手法・追加 ~25分）
  - メタデータ: 実行パラメータ・git rev・wasm ビルド時刻・シード（再現性要件）
- ブックは**このダンプのみ**から構築する（run1 の JSONL との一致確認はサニティとして
  実施するが、依存はしない）。コスト: フル再実行 ~4.5h + 生存手導出 ≈ 一晩で完了。
- 白8 エントリの invariant: **「ダンプ内でチェック済み、かつ強制負けなしの手」だけが
  ブックに入る**（トラップ局面は検証済み生存手、生存手ゼロの局面はブックに**入れない**
  = 探索フォールバック + 彗星型として記録）。

## 2. 配信と配線（設計レビュー S1/S2 反映）

- **新モジュール `src/logic/cpu/openingBook.ts`**（`opening.ts` には手を入れない）:
  canonical 化 → ルックアップ → 逆変換の同期 API + 資産の遅延ロード。
  **対局 worker（cpu.worker.ts）からのみ import** — review.worker.ts は opening も
  DIFFICULTY_PARAMS も import しない現構造のため、**構造的に振り返り非適用が担保**される。
- 適用条件: `BOOK_ENABLED_DIFFICULTIES = ["hard"]` の専用定数（DifficultyParams 型は
  変更しない = 他難易度・既存テストに波及なし）。白番・ply≤8・ブックヒット時のみ。
  ミスなら従来の探索へ。
- 資産 `src/assets/opening-book-hard.json`: まず **plain string key（canonical 225字+手番）
  で実装し、gzip 後サイズを実測**。問題があれば BigInt ハッシュ化（hash 関数は build/runtime
  で SSoT 共有、ビルド時衝突ゼロ検証）に切替（設計 S3: 複雑化は計測で正当化されたときのみ）。
- 逆変換: `boardSymmetry` に「argmin 変換の取得 + 座標の逆写像」を追加（API 拡張）。
  自己対称局面では argmin が複数あり得るが盤対称で等価なのでどれでも安全（一行注記 +
  **stabilizer 非自明な局面でブック手が正しいセルに戻るユニットテスト**を追加。設計 S4・
  イシュー S6）。

## 3. 振り返りとの整合（イシュー B2 の解消）

- 問題: トラップ局面のブック手（生存手）は「素の探索が選ばない手」。振り返りが素の探索で
  注釈すると、**ブックが避けた敗着を「より良い手」として推奨し得る**（ユーザー向けの
  ミスリード）。
- 対応: 振り返りは着手選択にはブックを使わないままとするが、**注釈段階でブック資産を参照し、
  「打たれた手がブックに一致する場合は『定石（ブック手）』ラベルを付け、ミス判定と
  代替推奨を抑制する**（対象は ply≤8 のブック一致手のみ。資産の再利用であり、
  review.worker に openingBook の「注釈専用 API」だけを import する — 着手 API とは
  シンボルレベルで分離、worker バンドルには tree-shake で着手 API が入らない）。
- **例外（実装レビュー反映）**: 振り返りが当該手に強制負け（forcedLossType）を検出した
  場合は good 強制せず通常判定を出す（「定石なのに被詰み」の矛盾表示を防ぎ、将来ブックが
  古くなった場合も誠実な表示を維持）。
- 用語注記: 「定石（ブック手）」のラベル文言はボスレビューで要確認（「定石」は確立語、
  「ブック手」はエンジン用語の補助表記）。

## 4. 彗星ルートの個別対応（v1 と同じ）

白6 候補のミニ採掘（~5×20 チェック ≈ 15分）で「全滅 ply-7 を配下に持たない白6」に
差し替え。白4 まで遡っても解がなければ「黒必勝級の可能性」として記録しボス報告。
ダンプ実行に統合（彗星の白6 差し替え後の部分木を追加列挙）できれば一晩に同梱。

## 5. 検証ゲート（事前登録・イシュー S4/S5 反映）

1. **トラップ封鎖**: severity-A 49 レコードの黒手順をブック有効 hard になぞらせ、全件で
   強制勝ち不成立。**ランダム候補はプール全手を決定的に列挙して検証**（1ドローではなく）
2. **regression-positions**: 全 PASS 維持
3. **挙動差の静的保証**（実装レビューで Elo ゲートから置換）: commit-bench の対局経路
   （cpu-bridge-worker → WASM 直呼び）はブック配線（cpu.worker）を通らず、かつブックの
   挙動差は敵対的列挙由来のトラップ局面に限られ自己対局では実質観測不能 = Elo ベンチは
   構成上 null テストになる。代わりにビルダーで **「非トラップ由来の全エントリ =
   ダンプの hard 実選択と完全一致」を assert** し、ビルドレポート（一致数・トラップ由来・
   彗星型除外数）を出力する。これにより「挙動差が検証済み生存手を持つトラップ局面に
   厳密に閉じる」ことが証明され、Elo 中立は構造的に保証される
4. **ブラウザ動作**: hard 対局でブック手使用のスモーク + 資産の遅延ロード確認 + 全テスト緑
5. **振り返り整合**: ブック手が「定石」ラベルになり敗着が推奨されないことをテスト棋譜で確認

## 6. 運用 runbook（イシュー S3 反映）

- **重み（PROSPECT_SCORE_DEFAULT）変更時はブック再生成を必須**とする（`--dump-book`
  権威実行 → build → ゲート1/2/5。トリガと手順を本書と AGENTS/plans に明記）。
  生存手の「強制負けなし」判定は戦術探索由来で重み非依存だが、hard 選択手の凍結は
  新重みの意図から乖離し得るため。
- ブック資産にメタデータ（生成元ダンプ・git rev・重み世代 texel-rN）を埋める。
