- quiet フィルタ（即五なし / hasVCF(200) なし / dedup）とラベル（Rapfi 100 ms、\|eval\|≤3000）は r2 と同じ。3 源とも**同じ関数**を通す（§2 の抽出）。
- 盤面キーはブック形式 `${boardToString(board)}|${stm}` に統一（コーパス独自の `b:/w:` 形式は廃止）。ブック行・prefix 行は `parseBoardKey` / 棋譜再生で盤面を作り、同じ `seen` で dedup。**dedup と回帰除外の照合は canonical key（対称正規化）で行う**（ブック key は canonical、棋譜は生の向きなので、生 key 照合では対称重複 118 局面がすり抜ける＝A1 レビュー実測）。行の `key` は生の向きのまま。r2 の dedup（生 key）とは意味論が変わる。
- `CorpusRow.source` に `kind: "kifu" | "book" | "prefix"` を追加。`groupKey` は kifu = `file#gameIdx`、book/prefix = 1 局面 1 グループ（親子局面が fold をまたぐのは許容）。
- 回帰ゲート局面（`regression-positions.ts` の `REGRESSION_POSITIONS` を lib に export）は `seen` に事前投入して学習から除外（テスト衛生。派生局面までは除外しない）。stats に `rejectedRegression` を出す。
- エンジン混在（06 は legacy 時代）は許容。源・月・ply 帯・手番の行数表を §4 に出す。
- 決定事項: ブックは再生成しない（Rapfi 誘導済み。asset の `weightGeneration` 乖離は許容）。ゲート起点局面（スイート 7 手）の学習含有も許容（leakage は軽微、記録する）。
- 配置: `bench-results/corpus/`（gitignore）。再生成手順は §5。旧 labeled JSONL とは key 形式が違うので resume は効かない（新規ディレクトリなので実害なし）。
- quiet フィルタの `hasVCF` は TS 版（局あたり 97 ms の主因）だが r2 と同一の事前登録定義なので本 PR では変えない。wasm VCF への差し替えはコーパス定義の変更として別途。
- prefix 行の大半は 09 棋譜の ply 4-6 と重なり kifu 側に吸収される（先勝ち）。合格条件は kind 横断の帯小計で見る。

- `prospect-texel.ts --k=5 --teacher=both --K=200`（rapfi 教師の fold 平均 val が主指標、outcome は参考）。`prospect-anchor.ts --min-support=100`、アンカー 6 セル据え置き。

- **事前反証 (ii) 差分の振り幅**: r2 → r4 の 34 セル差分（量子化後整数）を表にし、S4/S4' の勾配（±100 で ±10 Elo）と照らす。差分が希少セルだけで振り幅がその範囲内なら固定スクリーンを省略して「飽和」と結論してよい。
